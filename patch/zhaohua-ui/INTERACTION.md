# 造化鼎 · 交互与权限设计 V0.1

> 界面做出来只是"看得见"，这份文档回答的是"怎么用、怎么点、谁能写"。
> 三条原则：**先看后改、改前先演、写必留痕**。

---

## 一、三个入口，各管一段

| 入口 | 在哪 | 回答的问题 | 权限上限 |
|---|---|---|---|
| **A 启动层** | 开机第一屏「造化鼎」按钮 | 现在总体什么状态？该先修什么？ | 只读 + 预览 |
| **B 画布节点** | 乾坤鼎画布里插入的 `ext-zhaohua` 节点 | 眼前这个技能/这一层好不好？ | 只读 + 预览 |
| **C 对话** | 乾坤鼎的 agent 直接调 `zhaohua` 工具 | "帮我看一下这个技能" | 只读（写需你点头） |

**一个技能在三个入口看到的是同一份数据**——都来自 `zhaohua inspect/audit`，不是三套实现。
入口只决定"看的角度"，不决定"看的真假"。

---

## 二、主流程：五步，三步有闸门

```
① 看（只读）
   inspect → 这是什么、缺什么、能不能评审
   audit   → R01–R10 哪几条不过
        ↓
② 诊（只读）
   UI 把失败项拆成三类：
     · 真缺陷（R02/R03/R09）→ 可以修
     · 约定冲突（R06/R10）  → 不是错，是尺子不认跨技能共享
     · 需人工（R08/R11）    → 机器不猜
        ↓
━━ 闸门 1：动手之前先看配方 ━━
③ 演（预览，不落盘）
   fuse / create --dry-run → 出「合并后的 SKILL.md 差异」
   守卫全绿才允许下一步；V01 字节超预算 → 先商量怎么砍
        ↓
━━ 闸门 2：写回之前先看 diff ━━
④ 改（写，需确认）
   落 staging/ → 复验 audit → 通过才写 data\skills\<name>\
   写前自动备份、写后自动复验、失败自动回滚
        ↓
⑤ 证（写证据）
   每次动作落一份 EVIDENCE.md / registry.jsonl：
   谁、什么时候、拿什么来料、改了哪几行、审计从几改到几
```

关键点：**③ 和 ④ 是两个动作**。预览阶段永远不落盘，所以"看配方"没有风险；
真正写的时候，屏幕上必须能说出"这次改哪几个文件、改多少行、能不能回滚"。

## 三、权限四级（这是核心设计）

| 级别 | 能做什么 | 触发方式 | 风险 |
|---|---|---|---|
| **L0 只读** | inspect / audit / 看证据 / 看差异 | **默认**，不需要开关 | 零 |
| **L1 预演** | 生成 staging 副本、算 diff、算重叠率 | 点「预览」，落 tmp 目录 | 零（可清理） |
| **L2 写工作台** | 把技能写进 `data\skills\`、装包、回滚 | **每次都要确认**，且自动备份 | 中：会改变 agent 的行为 |
| **L3 写引擎** | 改造化鼎引擎、改 product.json 规则 | **不在 UI 里做**，只跑 CLI + 人工审 | 高：会改变"尺子"本身 |

实现上只有两个开关，别做成权限矩阵：

- `allowWrite`（工具/UI 配置项，默认 **关**）——关着时 L2 动作直接拒绝并说明原因；
- 每个 L2 动作前弹一次**确认条**：`将写入 3 个文件（+128 / −41 行）· 已备份到 _backup/20261115-160500 · [写入] [取消]`。

L3 明确不做进界面，理由：**尺子自己不能一边量一边改自己**。

## 四、人必须点头的三处

1. **合并前**（闸门 1）：配方里有几个来料块、禁区继承几条、字节预算多少 —— 不看这个就合，等于闭眼改 prompt。
2. **写回前**（闸门 2）：diff 的增删行数、影响哪几个阶段、能不能一键回滚。
3. **安装前**：与已装包的重叠率 > 80% 会被拒，界面要把"和谁重、重多少"直接说清楚，而不是弹个错。

除此之外不打扰：看、诊断、算差异，全都不需要点第二下。

---

## 五、agent 调用时怎么"允许"

对话里 agent 调 `zhaohua` 工具，规则简单：

- **只读动作**（status / inspect / audit）→ 直接跑，结果进上下文；
- **写动作**（verify --evolve、写回、装包）→ 工具**先拒绝**并回话：
  「这需要写 `data\skills\film-cinedance\`，影响 X 处。要我把 diff 给你看，还是你直接授权？」
  → 只有你在对话里明确同意，下一轮才带着 `allowWrite` 跑。

这比弹窗可靠：**弹窗会被无脑点掉，对话里必须打字同意**。

## 六、失败、冲突、回滚

| 情况 | UI 表现 | 机制 |
|---|---|---|
| 写回时文件哈希变了（你手工改过） | 拒绝，并显示"当前文件与预览时不一致" | 预览时记 sha256，写前比对 |
| 复验不通过 | 自动回滚，红条："已回滚，原因 R03" | 备份 → 写 → 复验 → 失败还原 |
| 装包撞车（重叠率 > 80%） | 黄色警告 + "和 film-cinedance 重 87%" | `pack-install --overlap-threshold` |
| 升级后丢了改动 | 概览页一条："检测到安装版本变化，建议重放品牌补丁" | 比对 `version.json` 与 patch 基线 |

## 七、空状态与首次使用

第一次打开时**不要**直接甩一个全红的表：

```
还没有体检过。
[ 开始体检 ]  约 30 秒，只读，不会改任何文件。
```

跑完才出现 47 条失败 —— 而这时你已经知道它是**怎么来的**（12 个技能共用一套 references），
所以第一屏的第三张卡永远写着"下一步该做什么"，而不是"你坏了多少条"。

## 八、还没定的事

1. **B 入口（画布节点）到底展示什么**：全量表格？还是只看当前选中的技能？
2. **预览 diff 用文本还是双栏**：单文件双栏、多文件用列表 + 展开。
3. **要不要"一键全修"**：R02/R03/R09 可机械修，但一次改 15 个技能的风险需要评估 ——
   当前建议：**逐层修**，每层改完复验，不提供全选。
