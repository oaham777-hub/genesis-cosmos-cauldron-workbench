# 02 角色圣经 / Character Bible

## 合作方式与试写边界

继承总控的[合作方式](references/cooperationModes.md)和作者本轮目标。正式成果以确认依据为准；试写可使用明确标注的草稿、片段和假设，不把本Skill的生产输入要求当成讨论或返回的硬门禁。作者明确要求修改时直接出新草稿，不再重复询问是否开始；不自动确认、覆盖原件或执行收费生成。

执行 [编剧质量接力](references/story-development-quality.md) 的 02 小节：完整人物标准不缩水，声音与知情状态须能进入后续对白和跨集连续性。

涉及事实改稿、06 回退或长对话恢复时，执行总控的 [改稿联动与原件交接](references/revision-impact.md)：本集后文与已写后续集一起检查，完整新版与差异先保存，确认后才使真实依赖的下游过期；不靠一句局部替换或摘要代替原件。

进入本阶段（含直接调用）先执行 [九阶段菜单与保存位置](references/stage-entry-and-paths.md)：显示本阶段中英标题，按规则展示并保存当前阶段菜单选择；所有读写先解析实际项目路径。此入口不改变本阶段的专业边界。

读取 `references/source.md` 作为方法来源。

输入仅限：`00-项目管理/artifact-registry.md` 登记的最新已确认概念锚定（或中途进入/从 06 退回时用户锁定的外部剧本原稿），以及 `00-项目管理/reference-memory.md` 中已经由用户确认、状态为“启用”、使用范围包含“故事创作（01-05）”且阶段适用图包含 02 的人物、关系或人物弧方法。没有适用参考时完全按原流程执行，不得主动检索。

## 强制要求与输出规范

1. **长在概念锚定上**：大纲（01）里已经确定的人物姓名、身份、核心目标与结局方向，一个字都不许改。项目定位 E 时读取 `references/e-fast-production.md`，按本阶段完整标准从已确认故事自动生成**文字角色圣经**，只省去作者填表，不缩减核心人物交付；人物定妆图片归 07 Lira。
2. **从外部剧本反推提取基线（仅限中途进入且从 06 退回 02 时）**：若用户最初只提供了完整剧本（02 为 `未开始（未独立提供）`），而 06 压力测试指出人物动机或声音有问题需回 02 修改，**不得凭空编造**。必须先从外部剧本提取主角动机、语声与关系，标明每一条的场次/台词出处，存为 `02-角色圣经/characters-v001.md` 交作者核对（「我从原稿提取的基线是这样，对吗？」）；作者确认 `v001`（或核对修改出 `v002`）后，再按病灶修订出下一版本号。
3. **声音或行为可辨测试**：有对白的作品做去名字台词盲测；无对白／极少对白作品改做去名字行为辨识，不凭空造台词。B 电影节人物不默认创伤、死寂或失语，C/E 人物不降为受辱、打脸和震惊的功能位。
4. **输出、版本卡与知识库应用单**：创作输出仅限 `02-角色圣经/characters-vNNN.md`（云文件夹单目录模式对应 `02-角色圣经-vNNN.md`），文件末尾必须附上**【版本卡 · 02 角色圣经】**（锁死主角说话特征供第 05 道使用）。若加载了本地参考方法，必须同时创建 `00-项目管理/参考应用单/02-characters-vNNN.md`，逐条写明实际落到哪个人物、关系、欲望、弱点或人物弧；无法落地的写明原因。应用单只做审计，不混入角色圣经正文。每次完整修改先扫描已有文件取得下一个三位版本号，保存为草稿并登记；用户确认后由总控同时确认角色圣经及其应用单。

项目事实和当前分支 Skill 规则高于参考方法。参考方法与概念锚定冲突时标记待复核，不得为了套参考改变用户人物设定。

禁止：改写故事大纲、生成世界观、分场、剧本、压力测试报告、图像提示词、表演或视频提示词。

完成后标记“待人工确认”，附上版本卡，并停止等待确认。
