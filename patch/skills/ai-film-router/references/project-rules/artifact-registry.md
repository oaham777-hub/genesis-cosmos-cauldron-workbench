## 固定状态与适用性标记

- `未开始`（含备注 `未开始（未独立提供）`）：尚未执行，或用户中途进入时未单独提供该上游文件。
- `草稿待确认`：已经写入本地，但不能交给下一步骤。
- `已确认-当前`：本流水线经用户明确点头确认的当前唯一有效版本，可进入下游。
- `外部提供-已确认`：用户带进来的原稿基线，原样留档可进入下游；若下游回退要修改它，需先提取/反推出 `v001` 并经作者核对。
- `已完成-结论`：**仅 06 压力测试报告使用**，代表报告已经完成，结论另记为通过、需要修订或证据不足，不代表自动授权改稿。通过且没有未解决必改病灶时，处置记为不适用并关闭本轮修订，不要求再选一次改稿授权，也不自动进入07。
- `已作废（不合格）`：**仅 06 压力测试报告使用**，代表报告未指明最弱一环或未写病灶道号，需重审出新号，前五道不动。
- `历史已替代`：曾经确认过，保留查阅，不再默认使用。
- `已过期-禁止使用`：依赖的上游已经改变并确认，不得继续生成或交付（但保留原文件不删）。
- `缺文件-阻断`：登记路径不存在或不可读，必须先修复。
- 适用性标记：`已跳过` / `不适用`（如现实题材跳过 03，或用户选择跳过 06），不占版本号。

## 维护规则

1. 每次形成可供用户检查的完整成果，先写入新的 Markdown 版本并确认文件存在，再登记为“当前草稿”和展示；修改不得覆盖旧版本。
2. 用户确认前，旧的最新确认稿仍有效；新草稿可以作为标明依据的跨阶段试写输入，不能自动替换正式基准。用户明确采用后，新草稿才升级为“最新已确认”。
3. 同一阶段恢复时读取“当前草稿＋最新已确认”；正式制作默认读取最新已确认版。进阶/高手或作者明确要求试写时可读取上游草稿与片段，列明未确认状态，不虚构有效依赖，不因仅为草稿而阻断讨论。
4. 新版本确认后，旧确认稿变为“历史已替代”；依赖旧确认稿的下游立即变为“已过期-禁止使用”，不能继续作为默认输入。
5. 01 至 06 可以按整阶段登记；07 按角色/场景/状态 ID，08 按场次 ID，09 必须按场次建立 `09-镜头与视频提示词/镜头规划/<场次ID>/scene-registry.md`，避免修改一处使全项目重跑。
6. 09 的合作档位、导演方案、时长、镜头清单、生成单元、空间图、连续性、分镜图绑定、视觉质检、关键帧和各模型提示词分别登记。提示词必须写明依据的镜头清单、生成单元、空间图、连续性、实际参考图、视觉质检、关键帧、资产、ACTING 和目标模型版本。
7. 新镜头清单确认后，依赖旧清单的生成单元与提示词包立即“已过期-禁止使用”。只改生成单元分组或时间戳时，仅受影响模型提示词过期，镜头清单仍有效。新包只重编受影响内容，未改镜头继承并写明来源。
8. 用户给的是已有标准剧本时，先把原文件登记为“作者锁定原剧本”（状态 `外部提供-已确认`），按需执行 06 后生成生产拆解；不得把原稿与 05 生成剧本混为同一成果。
9. 版本统一使用三位数 `v001`，**各阶段独立计号，严禁跨阶段机械同号**。生成新版本前扫描同目录已有文件取最大编号加一，不得靠聊天猜编号。
10. 写文件采用“临时文件写完后替换”的方式；文件成功后再更新登记。任一步失败都保留旧确认稿并立即说明。
11. 同一项目同一时间只允许一个 Agent 写入。能运行 Python 时先调用 `artifact_guard.py acquire-lock`，完成后释放；检测到其他 Agent 的锁时停止写入。
12. 旧项目升级时保留旧登记表备份，再建立 V4 登记；旧记录未迁移完成前不得假装版本已经确认。
13. 02、03、05 加载本地参考方法时，必须登记对应 `reference-applications` 应用单；应用单没有具体落点时不能把参考标记为已采用。
14. 每个正式任务登记素材方式与真实职责；实际用图才要求图文件，严格首帧才要求开头图。文字任务写全状态并标视觉未验证，改变素材确认后仅使真实依赖的旧质检和提示词过期。
15. 04 时长是写作预算；05 每份完整剧本草稿必须登记成稿时长复核；06 做结构与慢节奏留白复核。09 不得直接照抄 04 数字，必须结合 05 成稿、08 ACTING 和当前镜头重新核算。
