# AI 影视项目弹性总控（V4 · 01–09 九阶段）

本项目配套 `ai-film-router`。用户提出影视创作请求时，先读取当前用户 Skill 目录中的 `ai-film-router/SKILL.md`。

合作方式依本轮APP设置或作者最新选择，遵循总控的`references/cooperationModes.md`。新手推荐下一步；进阶和高手可跳步、返回、先试后定。草稿可以作为明确标注依据的试写输入；导航不等于确认或作废，讨论时保留旧稿，正式采用新版后才处理受影响下游。作者已经明确确认并要求继续时接力下一专业Skill，不重问同一许可；新产生的稿件仍待采用。旧模板中把试写也卡在确认门的规定按此解释。

进入任一阶段先执行总控的 `references/stage-entry-and-paths.md`：阶段与增强菜单显示中文名称、英文名和用途；按实际项目布局解析所有目录。新项目使用 01–09 中文成果目录，旧项目保留原目录，绝不在原项目旁新建第二套成果。

1. 新项目第一轮先判断入口：A 从零创作；B 已有完整标准剧本；C 已有部分资料；D 高手镜头优化。入口不清楚时只问这一次，记录后不重复。
2. 一次只调用一个专业 Skill，但允许用户主动切换到任意阶段（01 概念锚定、02 角色圣经、03 世界观可选、04 分场大纲、05 剧本深度融合、06 剧本压力测试可选、07 Lira 图像资产、08 ACTING 表演、09 CINEDANCE 镜头与视频提示词）。
3. 没有用户明确要求和确认，不改掉其他阶段已经确定的内容；用户要求修改上游或根据 06 剧本压力测试报告获授权回退时，留版本、切回该阶段并标记受影响下游。
4. 用户已有剧本、角色卡、资产图或表演文件时，只登记他明确指定的权威输入（标记为 `外部提供-已确认`，未独立提供的上游标记为 `未开始（未独立提供）`），不强迫重跑无关前序。完整标准剧本先询问是否需要先走 `06 剧本压力测试`；不走或审完后做接管检查，由总控生成包含逐场时长初估和下一步路线的生产拆解（`05-正式剧本/production-breakdown-vNNN.md`），未经授权不得改写作者剧本。
5. 首次确认 05 后，询问是否进入可选的 `06 剧本压力测试`；已授权修订的新确认稿默认按已选路线继续制作，不自动重进06；作者明确选择复审时才审受影响范围，不重复询问原有改稿授权。未复审时旧报告不覆盖新版，也不阻断作者选择的下一步。报告登记为 `已完成-结论`，另记通过、需要修订或证据不足。通过且无未解决必改病灶即关闭本轮修订，不再套用改稿选项；只有新病灶或超出原授权才补问。作者拒绝审查时记为 `已跳过`；跳过或通过均不隐含进入 07/08/09，后续按作者明确路线执行。
6. 06 退回遵循“事件缺失回 04、表现不足回 05”与“缺事件三档最小代价补法”；新版 04 确认且与 01–03 无冲突时，05 直接按新版 04 重锁场次表并附新旧场号对照，不把场数变化误报为上游矛盾。
7. 用户可以直接说“只做 CINEDANCE”“从 Lira 开始”“先做剧本压力测试”“回到剧本阶段修改第 8 场”。
8. 项目模板和空目录中不得写入示例故事、角色、资产或旧项目内容。
9. 每个阶段的完整结果必须**先保存到项目版本化 Markdown 文件（含结尾版本卡）**，再同时完整显示在聊天窗口，不能只回复文件路径。
10. 用户在聊天中修订后，先写入新的 Markdown 版本并更新 `artifact-registry.md` 与 `artifact-state.json`；旧版本保留，各阶段版本号独立递增（`v001 → v002`）。同阶段恢复读取当前草稿与最新确认，下一阶段只读取状态为 `已确认-当前` 或 `外部提供-已确认` 的版本。
11. 每个阶段开始前读取 `00-项目管理/project-status.md`、`00-项目管理/routing.md`、`00-项目管理/artifact-registry.md`、`00-项目管理/artifact-state.json`、`00-项目管理/session-checkpoint.md` 和 `00-项目管理/reference-memory.md`，只加载状态为“启用”且适用当前阶段的参考编号；用户最新确认的项目文件始终优先。02、03、05 使用参考方法时必须同时生成阶段应用单，写清具体落点，不能把“已读取”冒充“已融合”。
12. 进入 07 Lira 前必须已有可供生产使用的角色状态、场景与道具资料；缺少时先从最终剧本提取为独立生产资料，不把剧本改成提示词。
12.1 从零项目的 04 时长只是写作预算。05 每次完整剧本草稿必须生成成稿时长复核；06 做结构与慢节奏停顿复核；硬时长超限在确认 05 前处理，08 加入演员停顿与反应，09 才做最终镜头核算。
12.2 第 04 阶段写场次事件和对白意图，不预写完整台词，也不强制每场固定节拍；第 05 阶段以最新已确认 01–04 为主写正式对白。知识库启用时只把经用户确认且适用本阶段的方法卡加入约束，不让参考片改写作者故事。
13. 09 CINEDANCE 阶段首次保存项目默认快速出片／一起打磨／自由掌镜合作档位，后续沿用、可改默认或只覆盖某场；仅换档不作废已确认镜头。再在同一阶段完成拍法与时长、逐镜清单及独立的生成单元、实际分镜图绑定与视觉质检，最后为已确认版本编译 Seedance 2.5、Seedance 2.0、MiniMax H3 或多版本提示词。Seedance 2.5 最长 30 秒是一次多镜头生成单元上限，不强制一个固定镜头或凑满 30 秒。
14. 正式视频任务按 CINEDANCE 的 reference-materials.md 区分剧情／人物参考、严格首帧或文字生成。只有严格首帧任务才要求开头图；各模式均写全人物、场景、站位、动作、光影、道具和台词，不使用含糊历史指代。
15. 快速出片档后台启用基础导演顾问，只展示简短拍法与镜头表供一次确认；一起打磨档给关键取舍与完整菜单入口；自由掌镜档可展示完整专家菜单。所有档位均可说“查看全部增强”。后续场次继承项目默认或按场次覆盖；新打戏、大招或复杂调度仅一行增量建议，不静默启用专项。
16. 用户确认、否定或修改重要事实，系统生成较长草稿，准备切换 Skill，或平台提示上下文压缩时，后台更新 `00-项目管理/session-checkpoint.md`。成功后只在回复末尾报告一次保存路径，不反复询问；写入失败必须立即说明，不能假装已经保存。
17. 检查点中的“未确认想法”不得当成正式事实。切换 Skill 时先保存检查点，再只把最新已确认文件、必要上游事实和当前阶段启用方法写入新路由；上一阶段的无关方法与候选内容不得继续携带。
18. 每次完整成果和每次修改都生成三位版本号的新版本。新镜头清单确认后，依赖旧清单的生成单元和提示词标记为“已过期-禁止使用”；仅调整生成单元分组或时间戳时，受影响模型提示词过期、镜头清单不作废。只重编受影响镜头与单元，未改镜头继承登记。
19. 07 按资产 ID、08 按场次 ID、09 按场次与模型登记影响范围。空间图、分镜图绑定、视觉质检和关键帧都必须登记版本；镜头、图片或连续性改变后不得继续使用受影响的旧提示词。
20. 同一项目同一时间只允许一个 Agent 写入；检测到其他 Agent 的项目写入锁时停止修改。文件写入成功后才能更新登记表。

## 可选专家增强

1. `film-expert-bridge` 只增强当前阶段，不取代原专业 Skill。
2. 01–05、07、08 第一次进入增强选择时先显示最匹配的 1–3 项及当前阶段完整一级菜单。09 先选合作档位，按档位控制菜单展示；用户可随时说“查看全部增强”。选择前不加载未选专项正文；快速出片档的选择已授权基础导演顾问。09 的选择保存为项目级默认，后续场次不重复整套菜单。
   每个选项必须同时显示“中文技能名称 / English Name（内部编号）——一句用途”，例如 `台词像人说话 / Natural Dialogue（05-A）——删除解释性废话并补真实回应`；禁止只显示编号或只显示 A/B/C 字母。兼容旧编号（`06-A~J` → `07-A~J`，`07-A~G` → `08-A~G`，`08-A~Q` → `09-A~Q`）。
3. 用户不选而直接继续时，记为本阶段“照原流程”，09 保存为项目级默认；不得卡在选项页或反复提示。
4. 用户选定前不读专家正文。选定后先定向读 1–2 份最相关资料，证据不足时继续补读，不得猜测。
5. 首次启用时创建 `00-项目管理/expert-memory.md`。每轮先读项目最新文件和该记忆，不依赖长对话记忆。
6. 完整菜单末尾显示“作者自定义”。先匹配已有技能；没有完全匹配时只建立当前项目、当前阶段专用的方法卡并等待确认，不得修改全局 Skill。

## 可选本地知识桥

本项目同时支持 `film-knowledge-bridge`，但它不是创作阶段，也不改变 01 至 09 的路由。

1. 新项目确认入口模式后、首份创作成果前，若项目仍是“菜单未询问”，主动显示一次知识库 A/B/C；显示菜单不检索。
2. A 表示关闭并照原流程，B 表示智能匹配 3 至 5 部剧本和方法书，C 表示只查方法书。保存选择；B/C 才检索，同一项目不重复询问。
3. 学员不需要提供电影名。知识桥自动提取题材、结构、冲突、人物关系、情绪、制作规模和文化背景。
4. 多部参考必须分工，只迁移结构、人物方法、氛围或视听技巧；不得拼接剧情、复制核心诡计、人物组合、标志性场面或对白。
5. 知识卡先在聊天中完整展示并等待确认；只有确认后的知识卡才能作为当前专业 Skill 的附加参考。只有真实本地路径、页码和命中词齐全时才算本地命中。

## 跨阶段参考记忆

1. 候选知识卡不自动进入后续阶段。用户明确确认采用后，才写入 `00-项目管理/reference-memory.md` 并分配参考方法编号。
2. 条目必须记录来源、本地路径、页码与命中词、允许迁移的方法、使用范围、绑定的项目事实和禁止借用内容。故事类方法默认“故事创作（01-05）”。
3. 进入新阶段时，先读取完整参考记忆，再自动加载使用范围包含当前任务的启用条目；只用一句话报告编号，不重新检索。
4. 用户可反复增加、采用、停用、恢复、删除或替换参考；每次先实时写入文件。普通删除只停用留痕。
5. 用户指定喜欢某部作品的某个动作、场景或手法时，先定向检索该来源并等待确认，再写入新条目；不得把用户说的片名直接当作已经核实的本地来源。
6. 第 05 阶段必须以最新已确认的概念锚定、角色、世界观和分场为主，再使用适用的参考方法。任何参考与项目事实冲突时必须停下询问，不能静默改写。
7. 02、03、05 输出时，参考方法必须另存阶段应用单，逐条写明人物、关系、世界规则、场次、动作或对白的实际落点；没有落点不能声称已融合。

## 01 与 05 强制检查

- 从零进入 01 且定位未明确时，第一条创作回复显示 `film-synopsis/references/source.md` 的洋子项目定位 A/B/C/D/E 菜单并停止；用户已明确选 E 等定位时直接沿用。入口 A/B/C/D 与作品定位 A/B/C/D/E 是不同问题。E 是快速出片编剧路线，不是第十阶段。
- 进入 05 时，自动迁移旧项目“适用阶段”字段中属于故事方法、只标了 `01`、`04`、`01/04` 或部分阶段的条目为“故事创作（01-05）”，并加载所有启用的故事参考；不得因为标签遗漏重新搜索目录。

如果本机尚未安装 `ai-film-router`，提示用户先完成课程包安装，不自行虚构路由规则。
