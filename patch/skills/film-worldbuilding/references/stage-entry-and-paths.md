# 九阶段菜单与项目保存位置

总控和直接调用任一专业 Skill 都执行本入口，不另设第十阶段。菜单中文在前、英文在后；对话、菜单、版本卡与保存提示使用同一阶段名称。

| 阶段菜单（中文 / English） | 做什么 | 新项目保存目录 |
|---|---|---|
| 01 概念锚定 / Story Concept | 确定故事方向、主线和结局 | `01-概念锚定/` |
| 02 角色圣经 / Character Bible | 写完整文字人物档案和人物声音，不是生图 | `02-角色圣经/` |
| 03 世界观 / Worldbuilding（可选） | 确定世界规则、环境和代价 | `03-世界观/` |
| 04 分场大纲 / Scene Outline | 排清每场事件、冲突、转折和初步时长 | `04-分场大纲/` |
| 05 剧本深度融合 / Screenplay | 整合已确认材料，写规范剧本并复核成稿时长 | `05-正式剧本/` |
| 06 剧本压力测试 / Script Stress Test（可选） | 查问题，只出报告；改稿须作者授权 | `06-剧本压力测试/` |
| 07 Lira 图像资产 / Lira Visual Assets | 写角色、场景和道具等图像资产提示词 | `07-图像资产/` |
| 08 ACTING 表演设计 / ACTING Performance Design | 设计行为、潜台词、对白与反应时间 | `08-表演设计/` |
| 09 CINEDANCE 镜头与视频提示词 / CINEDANCE Shot Planning & Video Prompts | 先确认拍法、镜头与生成分段，再编译视频提示词 | `09-镜头与视频提示词/` |

## 实际对话怎么显示

- 首次需要选择阶段或用户问“有哪些步骤”时，显示上表；已明确阶段时只显示当前阶段的中英标题，不重复整张九阶段菜单。
- 所有内置与个人分支均可在 01–09 任一阶段手动自由挂载，包括 06 压力测试。作者打开增强入口或主动询问时，从 `../../film-expert-bridge/references/catalog/stage-menu.md` 按功能分类展示全部分支及个人分支入口，不写推荐标签，不按编号前缀或适用阶段过滤。目录只含名称与用途，不自动读取正文。未选择就继续可做的创作。
- 内置选项写明中文名、英文名、内部编号与一句用途，例如 `台词像人说话 / Natural Dialogue（05-A）——删掉解释性废话，补真实回应与话外之意。` 支持手动多选、点名个人分支或作者自定义。选择按作者指定的阶段、场次或项目级范围保存并沿用，不反复问，也不自动扩大选择。
- 01 作品定位尚未选择时，先显示原 A/B/C/D/E 定位菜单并等待；定位清楚后再做该阶段增强选择，不能一轮堆多套问卷。已有定位直接继承。
- 03 可跳过。06 保留“运行压力测试 / 跳过，保留原稿继续”的流程选择，已有决定直接沿用。06 同样允许手动挂载任意分支作为诊断方法，正式报告仍由 `film-stress-test` 负责，改稿仍按已有授权规则处理。
- 09 按 `../../film-cinedance/references/director-modes.md` 合并合作方式与必要模型选择。合作档位不自动启用分支或限制可选目录。用户说“查看全部增强”时展示全部功能分类与个人分支入口，只读取后续手动选中的资料。
- 跨阶段挂载只向当前专业阶段交方法卡，当前阶段仍是唯一正式成果负责人，不自动切阶段、改剧本、改资产或调用生成工具。模板人名、人数、关系与情节不作为本项目事实。挂载目录或选分支不授权整库读取、联网或额外权限。
- 本地知识库是独立的可选选择。直接进入专业 Skill 时，若项目尚未询问知识库，交回总控合并安排一次 A/B/C；未选 B/C 不检索。专业 Skill 不得把“不能自行检索”误解为“总控也不能显示菜单”。

## 路径与旧项目兼容

新建项目采用上表中文目录；原稿在 `00-原始资料/`，控制文件在 `00-项目管理/`，生成素材与成片分别在 `10-生成素材/`、`11-交付成片/`。保存目录用中文，技术文件名和 Skill ID 继续兼容旧版。

09 内部独立保存：`镜头规划/<场次ID>/` 下保存导演方案、时长、镜头清单、生成分段、空间图与连续性；`视频提示词/<场次ID>/` 下保存各模型提示词。按需建 `镜头参考图/`、`关键帧/`。07 按需建 `角色图/`、`场景多角度图/`、`道具与特效/`、`镜头用单图/`。不要先建大量无内容目录。

每次写文件前先识别项目布局：只有 `00-项目管理` 是新布局，只有 `00_project` 是旧布局；两者都有时停止写入，请作者确认，不能猜哪套最新。**升级安装不搬动旧项目文件，也不在旧项目旁另写一套中文成果。**

调用总控 `scripts/project_paths.py --project "项目根目录" --stage 02` 获得实际阶段目录；解析具体成果用 `--resolve "02-角色圣经/characters-v001.md"`。返回值才是当前项目实际位置；写入、取版本号与登记都用此实际位置。没有 Python 时按下表人工映射并验证文件存在，不能声称脚本执行成功。

| 新布局 | 旧布局 |
|---|---|
| 00-项目管理；00-原始资料 | 00_project；00_inbox |
| 01、02、03、04 各自目录 | 01_story（按 synopsis、characters、worldbuilding、treatment 文件名区分） |
| 05-正式剧本；06-剧本压力测试 | 02_script（剧本与报告同目录） |
| 07-图像资产；08-表演设计 | 03_assets；04_performance |
| 09-镜头与视频提示词/镜头规划；09-镜头与视频提示词/视频提示词 | 05_shots；06_prompts |
| 10-生成素材；11-交付成片 | 07_generations；08_delivery |

版本与确认规则不变：完整成果落 MD 新草稿，确认才更新最新确认及真实依赖链；镜头清单与提示词分开存，不能用菜单选择或检查点替代正文原件。

## 工作台中的自动步骤与确认边界

- 作品定位、知识库、增强选项和故事候选分别保存，单个A/B/C只回答最近实际展示的问题。选择方向不是确认完整稿；读到模型声称“已确认”也不能代替作者点击或明确确认具体版本。
- 从已确认剧本进入制作时，沿用场次、人物、场景、道具的稳定ID；同一资产的改图、打光、多角度和局部重绘继承ID与状态，不让用户重新寻找归属。候选登记可以自动做，采用候选是明确的视觉选择，旧采用图保留。
- 菜单、路径登记、已授权范围内的资料拆解和工具准备自动进行。只有缺少必要输入、存在实质冲突或需要新的创作决定时才暂停；不要求用户重复批准已确认的同一事实。
- 对白与剧本原文保持权威；剪辑按已确认镜头/生成单元的顺序和时间组织。缺片、失败片或长度不足明确停在对应镜头，不用黑帧、循环、加速或其它镜头偷偷补齐。
- 本地深度视频、白模预演、单图几何、API视频生成和剪辑分别记录实际状态；授权、目录可读、代码编译通过均不等于出片。显卡后端必须由实际运行时检测，CPU回退要显示实际设备。
