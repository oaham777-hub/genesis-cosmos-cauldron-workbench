# 多模型适配（L6 · reference）

> 用途：同一份 12 维主版本，按目标平台改写为可提交格式。**主版本是唯一事实来源，适配只改组织方式，不改信息。**
> 来源：`_incoming/visual-skills-main`（image / video 多模型词表与适配）、`imports/director-studio`（06-seedance2-adapter）、`imports/seedance-storyboard-3.0`（`motion-compile` 面向 Seedance 2.5）、`specs/h3-profile.md`（MiniMax H3）。

## 一、平台对照表

| 平台 / 模型 | 乾坤鼎现有资料 | 支持等级 | 入口处置 |
|---|---|---|---|
| **MiniMax H3** | `specs/h3-profile.md`、`references/h3-dialect.md`；覆盖基础模式与 Ref2VA 全参考模式，具体输入形态/时长按档案分派 | **专用档案可编译** | 可进入 L6；先锁精确提示词模式、已覆盖的参考输入形态、时长 |
| **Seedance 2.0** | CINEDANCE V4、`director-studio/.../06-seedance2-adapter.md`、Seedance 2.0 词汇与参数资料；包括经豆包 Seedance 2.0、火山方舟或第三方 Seedance 2.0 端点使用该适配资料 | **有专用适配资料，可编译** | 可进入 L6；必须锁 2.0、按秒/按次、目标时长及资料覆盖的提示词模式/参考输入形态；不得套用 2.5 参数 |
| **Seedance 2.5** | `08-Q`、Seedance 2.5 motion-compile、九段模块化结构 | **有专用适配资料，可编译** | 可进入 L6；必须锁 2.5、按秒/按次、目标时长及资料覆盖的提示词模式/参考输入形态；不得套用 2.0 参数 |
| Kling / Veo / Sora / Runway / PixVerse / 豆包或火山方舟上的其他视频模型 | 现有资料仅有通用多模型写法，没有对应模型的专属能力档案与逐版本编译闸；“豆包 Seedance 2.0 / 火山方舟 Seedance 2.0”按上一行的 Seedance 2.0 适配范围处理 | **仅通用草案** | 不得标为平台已适配或可直接提交；可继续平台无关上游，或经用户明确选择后输出标注“未验证通用草案”的草案 |
| **Wan 2.1** | H3 档案只说明语序相近，未提供 Wan 专属完整档案 | **仅有方法类比** | 不视为已支持的平台；需补专属档案后才可进入平台专属 L6 |
| 其他未列平台 / 未列模型版本 | 无对应能力档案 | **未登记 / 不支持** | 平台专属提示词硬门阻断；不得用通用知识补齐后声称已适配 |

> **支持边界**：以上表示乾坤鼎现有规则有相应提示词方法，不代表连接平台、运行生成或实测成片。Seedance 2.0 与 2.5 当前共享部分 CINEDANCE 表达，但版本、槽位和参数必须分别核对。MiniMax H3 的 T2VA/I2VA/Ref2VA 等是输入模式；Seedance 2.0 的 A/B/C 是提示词组织模式，不等于平台全部生成/参考输入能力。仅可使用对应资料明确覆盖的提示词模式和参考输入形态；未列组合不视为已适配。发现能力档案缺项时如实标注，不能称为已验证。

> **硬门定义**：只有表中“专用档案可编译”或“有专用适配资料，可编译”的精确平台/模型/模式，才可产出平台专属正式提示词。仅通用草案、方法类比、未登记平台不得通过该硬门。

## 二、改写四步（仅适用于已通过平台能力硬门的目标）

```text
① 锁定不可变信息：人物身份 @绑定、时间轴、逐字台词与画面文字、关键道具状态
② 重排结构：按目标平台语序 / 分段 / 字段顺序重排
③ 适配参数：时长、画幅、帧率、镜头词表换成该平台可用词
④ 边界改写：负面约束 → 该平台允许的表达（H3 写正向末尾；Seedance 写 Avoid 段）
```

## 四、常见改写陷阱

1. 把「七段语序」硬套到 Seedance：错——Seedance 走 CINEDANCE 九段式。
2. 在 H3 里保留 Avoid/负面段落：错——会污染正向描述（判 FAIL）。
3. 为了压字数删掉音效轨：错——四轨不得缺（`S-11`）。
4. 把中文术语直译成英文习惯用语：错——术语按词表统一，不自创。
5. 把通用候选冒充专属适配：错——平台清单外或只有通用写法的目标不能进入正式平台编译。
6. 乾坤鼎整体支持多个平台，但一个项目只锁一个目标。用户明确更换目标时，旧平台产物标为过期，重新过 S-33 后再编译新版本；同一项目不并行保存多个平台提示词版本。

## 五、自检

1. 唯一目标平台、精确模型版本、提示词模式和资料覆盖的参考输入形态（如涉及）是否通过 L0 能力硬门并写入 `00_project/project-status.md`？
2. 改写后信息守恒表是否全勾？
3. 是否出现了平台特有禁令（H3 负面词、Seedance 缺 Must Keep 等）？
4. 术语是否与 `prompt-lexicon.md` 一致？
